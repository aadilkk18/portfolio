Locally-run AI assistant with Khowar language memory

What LEO is

LEO is a personal assistant I built end to end: a native Windows desktop app, a local language model, persistent memory and voice input. It runs on my own laptop with 8GB of RAM and no GPU, with no cloud service behind it. The name is a tribute to Lionel Messi.

The problem

Khowar is my first language, spoken in Chitral. No mainstream AI model has real Khowar training data. Ask one for a translation and it doesn't decline. It invents a word and states it as confidently as a real one.

I watched LEO's model do exactly that. When I told it the word was wrong, it kept defending it. A line in the prompt telling it not to wasn't enough.

The one rule

The model talks. It never supplies Khowar. Every Khowar word LEO says comes from a database entry that I taught it.

How it works, with a real example

The model understands the sentence. The database supplies the Khowar. Here is the loop:

  1. I teach it by talking.I type "how are you is kicha asus in khowar". There is no form and no fixed format.
  2. It confirms before saving.LEO says what it understood and asks yes or no. Nothing reaches the database until I confirm.
  3. I ask it back, in either direction."How do I say how are you in Khowar?" or "What does kicha asus mean?" The answer is read from the saved entry and placed in the reply by ordinary code, not by the model.
Example: a word it was never taught

If I ask for a word that isn't in the database, LEO says it doesn't know it and offers to learn it. It doesn't guess. It asks.

Each phrase can carry several Khowar versions, tagged by register: formal, casual, or for speaking to elders. I can correct or delete an entry from inside the conversation.

Safeguards on the teaching step

  • Grounding check. Both the English and the Khowar must actually appear in the message I just typed. The model once invented content I never wrote.
  • Self-reference rejection. An entry that maps a word to itself is dropped.
  • Current message only. A new entry has to come from the message I just sent, not from earlier in the chat.
  • Ambiguity is surfaced. When two entries match a question almost equally well, LEO asks which one I meant.

The order of checks

Every message goes through the cheap, certain checks first: direct questions the database can answer, a pending yes/no confirmation, a close match to a taught entry, then list paging. The model only gets what is left over. Early versions let the model route every message, and it misread casual phrasing.

Memory

Conversations are kept for about 30 days. Before they expire, LEO pulls out the durable facts (my job, my projects, my situation) and keeps them permanently. Small talk is filtered out. A relevance check stops an old fact from hijacking an unrelated question. Mine kept dragging my internship into everything.

It also takes voice input, transcribed locally, with a correction pass tuned for Pakistani-accented English.

Bugs I'm glad I hit

The invented word

The model fabricated a Khowar word and defended it under correction. The fix was to take the model out of Khowar entirely.

The old message that came back

An unrelated later message was read as continuing an earlier teach or delete action. The fix: a new entry must be justified by the message just sent.

A request that matched the wrong word

Filler like "khowar" or "tell me" matched a short taught word purely on text similarity. Those words are now ignored when matching.

Decisions I made

  • The model never supplies Khowar. This is enforced in code, not requested in a prompt.
  • Local only. Small models on modest hardware, with no cloud fallback.
  • Phrases before words. Composing new Khowar sentences needs real grammar knowledge, and a naive version would sound right and be wrong.
  • One user, one machine. It's my tool, not a product.

Where it stands

Paused for now. The core works. Finishing the rest needs more computing power and more people than I have.
